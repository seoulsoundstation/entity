# Naver Blog Archive 0.2

공개 네이버 블로그를 Markdown으로 백업합니다. Windows 프로그램 창에서 블로그 주소와 저장 폴더를 선택해 전체 백업, 중단, 이어받기, 저장 파일 검사를 수행할 수 있습니다. SQLite에 글·이미지·실행 결과를 기록해 중단 또는 부분 실패 후 미완료 작업을 재처리합니다. 기존 명령줄 기능과 `legacy/` 스크립트도 유지됩니다.

## 시작하기 (Windows)

Python 3.10 이상이 필요합니다. Python 설치 시 **Tcl/Tk 및 IDLE** 항목을 포함하세요. 첫 설치에는 인터넷 연결이 필요합니다.

1. 프로젝트 폴더의 **`setup.bat`를 더블클릭**합니다. 의존성과 백업에 사용할 Chromium을 설치합니다. 설치 결과와 오류는 창에 표시됩니다.
2. 설치가 끝나면 **`start-gui.bat`를 더블클릭**합니다.
3. 네이버 블로그 주소 또는 ID를 입력하고 결과를 저장할 폴더를 선택합니다.
4. 이미지 저장·인용 원본 저장 등 옵션을 확인하고 백업을 시작합니다.
5. 진행 상태와 실패 내역을 확인합니다. 중단 후에는 같은 블로그와 저장 폴더로 다시 시작하면 이어받습니다.

### 자주 백업하는 블로그 저장

주소·저장 폴더·옵션을 입력한 뒤 **현재 블로그 저장**을 누르세요. 다음에는 **저장한 블로그** 목록에서 선택하면 그 블로그의 설정을 함께 불러옵니다. 설정 저장 또는 백업 시작 시에도 블로그 목록에 저장됩니다. 같은 블로그를 다시 저장하면 그 블로그의 설정을 갱신하며, 다른 블로그 설정은 유지됩니다. 블로그 선택 시 전체 원문을 다시 수집하는 갱신 옵션은 꺼집니다.

블로그 목록은 프로그램 시작 시 지정한 설정 파일 폴더의 `blog_profiles.sqlite`에 보관됩니다. 글 백업 DB와 별개이며, 글은 계속 블로그마다 지정한 저장 폴더에 보관합니다.

### 기존 글 건너뛰기와 원문 갱신

기본 **백업 시작 / 이어받기**는 매번 글 목록을 확인한 뒤 DB에 기록된 기존 Markdown·이미지의 파일 존재와 해시를 검사합니다. 정상인 글은 본문을 다시 내려받지 않고 **기존 파일 재사용**으로 건너뜁니다. 출력 형식 갱신이 필요하면 저장한 본문으로 Markdown을 다시 만들며, 예전 숫자 파일명도 제목 형식으로 바꿉니다. 이미 정리된 정상 파일은 다시 쓰지 않습니다. 새 글과 누락·실패한 항목을 처리하며, 이번 실행의 **저장/복구 · 기존 파일 건너뜀 · 확인 필요** 수를 구분해서 표시합니다. 저장/복구에는 신규 글 외에도 누락 파일 복원과 갱신 성공이 포함됩니다.

기본 모드는 원격에서 기존 글이 수정됐는지 다시 내려받아 비교하지 않습니다. 원문의 변경도 반영하려면 **기존 글도 최신 내용으로 갱신**을 선택하세요. 직접 수정한 로컬 Markdown은 이 경우에도 보호합니다. DB에 기록되지 않은 과거 백업 파일은 파일 존재만으로 정상 판정하지 않으며, 아래 기존 파일 처리 규칙을 적용합니다.

### 저장 글 ID와 검색

**저장 글 검색** 탭에서 고유 보관 ID, 네이버 글 번호, 제목, 본문으로 검색할 수 있습니다. 검색은 내 PC의 해당 블로그 DB에서 수행하며 한 페이지에 50개씩 표시합니다. 글 정보 확인, 보관 ID 복사, 저장 Markdown 열기를 지원합니다. 탭을 전환해도 클릭한 탭의 위치와 크기는 유지되며, 완료·실패 결과가 사용자가 선택한 탭을 강제로 바꾸지 않습니다.

각 글에는 `NBA-...` 형태의 고유 보관 ID가 부여됩니다. 같은 블로그의 같은 글은 다시 백업하거나 원문이 갱신돼도 ID가 바뀌지 않습니다. 기존 SQLite DB는 백업·검사·상태 확인이 잠금을 확보하고 열 때 버전 2로 자동 변환합니다. ID 추가를 위해 기존 Markdown을 다시 쓰지 않습니다. 실행 중인 백업과 함께 사용하는 검색 화면은 읽기 전용이며, 버전 1 DB도 파일을 변경하지 않고 같은 ID를 계산해 보여줍니다.

프로그램을 업데이트했다면 진행 중인 백업을 마치거나 중단한 다음 창을 닫고 `start-gui.bat`로 다시 실행하세요. 검색 목록에는 파일 경로가 있는 기록을 표시하므로, 누락 또는 부분 실패한 글도 상태와 함께 나타날 수 있습니다.

### 제목 파일명과 사진 읽기

새 Markdown은 **`글 제목 (네이버 글번호).md`**로 저장합니다. 한글 제목을 유지하고 Windows 파일명에서 사용할 수 없는 문자는 정리하며, 긴 제목은 줄입니다. 글번호를 붙이므로 같은 제목의 글도 덮어쓰지 않습니다. 파일명이 한 번 정해진 뒤 원문 제목이 바뀌어도 기존 경로와 보관 ID는 유지합니다.

**저장 결과 정리**를 누르면 기존 숫자 파일명을 제목으로 바꾸고, DB에 저장된 본문과 사진으로 Markdown 이미지·출처 링크를 다시 만듭니다. 인터넷 연결이나 재다운로드가 필요 없습니다. 사진이 11장 이상일 때 뒤쪽 사진 링크가 앞 사진으로 바뀌던 이전 출력 오류도 이 작업으로 바로잡습니다. 직접 편집한 파일은 보호하며, 그 파일이나 백업 범위 밖의 글이 참조하는 경로는 링크가 깨지지 않도록 변경을 보류합니다. 이 경우 확인할 항목에 이유를 표시합니다.

**저장 글 검색 → 글 선택 → 사진과 함께 읽기**를 누르면 기본 브라우저에서 본문과 사진을 함께 볼 수 있습니다. 별도 Markdown 뷰어를 설치할 필요가 없고, 사진은 화면 너비에 맞게 표시합니다. **저장 파일 열기**는 원본 `.md`를 기본 연결 앱으로 엽니다. Markdown을 메모장 같은 텍스트 편집기로 열면 사진 대신 이미지 문법이 보이므로, 사진과 함께 읽기 또는 Markdown 미리보기 기능을 사용하세요.

이미지를 오프라인으로 보려면 **이미지 저장** 옵션이 켜져 있어야 합니다. `.md`만 따로 옮기지 말고 `posts`와 `attachments`가 포함된 백업 폴더 전체를 함께 옮기세요. 받지 못한 사진은 **백업 시작 / 이어받기**에서 재시도합니다. 실패한 네이버 썸네일 프록시는 주소 안에 포함된 원본 사진 주소로도 재시도합니다. 새 수집에서는 본문 영역을 우선 선택해 프로필·메뉴 혼입을 줄입니다. 이미 저장된 본문의 추출 범위까지 바꾸려면 원문 갱신 옵션으로 다시 수집해야 합니다.

주소는 `https://blog.naver.com/블로그ID`, `https://m.blog.naver.com/블로그ID/글번호`, `PostView.naver?blogId=...` 형태도 지원합니다. 백업 범위는 입력한 블로그 전체입니다. 글 주소를 붙여 넣어도 해당 글만 백업하는 기능은 아닙니다.

백업을 시작하면 현재 설정을 자동 저장하며, 설정 저장 버튼으로 직접 저장할 수도 있습니다. 프로그램을 여는 것만으로 기존 설정 파일을 덮어쓰지 않습니다. 기존 `config.toml`이 있으면 불러오며, 다른 설정 파일은 아래처럼 지정할 수 있습니다.

```powershell
.\start-gui.bat --config "C:\내 설정\config.toml"
```

작업 중 중단을 누르면 안전한 지점에서 처리를 종료하고 결과를 보관합니다. 진행 중인 요청이 끝날 때까지 잠시 걸릴 수 있습니다. 이어받기에서는 저장한 본문을 재사용하고 실패한 이미지·출처를 다시 처리합니다. 원문의 수정 내용까지 반영하려면 기존 글을 다시 수집하는 옵션을 사용하세요. 저장 파일 검사는 네트워크 없이 파일 누락·변경·출처 연결을 확인합니다. 결과 폴더에서 Markdown과 `report.json`, 검사 후 `verification.json`을 확인할 수 있습니다.

GUI는 Python에 포함된 Tkinter를 사용합니다. `start-gui.bat`는 시작에 필요한 모듈을 확인한 뒤 `pythonw.exe`로 창을 열어 명령 창을 닫습니다. 시작에 실패하면 오류와 설치 안내를 표시합니다. Python을 새로 설치했거나 Chromium 실행 오류가 생기면 `setup.bat`를 다시 실행하세요. `pythonw.exe`가 없는 Python 배포판에서는 명령 창과 함께 실행됩니다.

명령줄에서 자동 설치하려면 기존 스크립트를 사용합니다. 아래 스크립트는 결과를 확인하는 일시 정지 없이 종료 코드를 반환합니다.

```powershell
.\scripts\setup.bat
```

이 명령은 프로젝트의 `.venv`에 의존성 및 Chromium을 설치하고, `config.toml`이 없을 때만 예제에서 복사합니다. 별도 Python 실행 파일을 쓰려면 `PYTHON_EXE` 환경 변수에 절대 경로를 지정하세요. 실행기는 `PYTHON_EXE`, 프로젝트 `.venv`, PATH의 Python 순으로 사용합니다. `PYTHON_EXE`로 지정한 Python에도 프로그램 의존성과 Tkinter가 있어야 합니다. `PLAYWRIGHT_BROWSERS_PATH`를 지정하지 않은 경우 설치한 프로젝트의 `.browsers`를 사용합니다.

## 명령줄 사용

`config.toml`에서 `blog_id`와 `out_dir`를 확인한 뒤 실행합니다.

```powershell
.\scripts\run-dev.bat backup --config config.toml
.\scripts\run-dev.bat status --config config.toml
.\scripts\run-dev.bat verify --config config.toml
.\scripts\run-dev.bat reformat --config config.toml
.\scripts\run-dev.bat gui --config config.toml
```

중간에 중단하거나 일부 작업에 실패하면 같은 `backup` 명령을 다시 실행합니다. 저장한 본문은 재사용하고 실패한 이미지·출처를 재처리합니다. 목록 수집은 첫 페이지부터 다시 확인하며 저장된 글은 다시 렌더링하지 않습니다. 수정된 글까지 가져오려면 `backup --config config.toml --refresh`를 사용하세요.

## 설정

`config.example.toml`의 모든 항목을 지원합니다. 알 수 없는 항목, 잘못된 자료형과 범위는 실행 전에 거부합니다. 상대 `out_dir`는 설정 파일 폴더를 기준으로 해석합니다. 블로그별로 서로 다른 `out_dir`를 사용하세요.

- `blog_id`: 주 블로그 ID.
- `out_dir`: 결과 폴더. 이전 백업을 이어 쓰려면 기존 Markdown이 들어 있는 폴더를 지정합니다.
- `delay`: HTTP 요청 및 글 렌더링 사이 최소 대기 시간(초).
- `download_images`: 이미지 로컬 저장 여부. false이면 원격 이미지 링크를 유지합니다.
- `follow_sources`: 인용 원본의 별도 저장 여부.
- `source_depth`: 원본 추적 깊이, 기본 1, 0~3. 순환 참조를 중복 수집하지 않습니다.
- `retries`: HTTP 및 렌더링 최대 시도 횟수, 기본 3.
- `timeout`: 요청/페이지 준비 대기 시간(초), 기본 30.
- `max_image_mb`: 이미지 한 파일의 최대 다운로드 크기, 기본 30 MiB.
- `max_pages`: 목록 무한 반복 방지 상한. 상한에 도달하면 미완료로 보고합니다.

이미지/출처 저장을 끄면 해당 자원의 오프라인 보존은 성공 기준에서 제외됩니다. 비공개·삭제된 글 또는 응답 차단은 오류를 기록하고 다음 실행에서 재시도합니다. 로그인·접근 권한 우회는 제공하지 않습니다.

## 저장 구조와 기존 파일

- 새 글: `posts/<blog_id>/<글 제목> (<post_id>).md` — 한 번 정해진 경로는 원문 제목이 바뀌어도 유지합니다.
- 이미지: `attachments/<sha256>.<확인된 확장자>` — 실제 이미지 형식을 검사하며 동일 내용은 공유합니다.
- 상태: `archive_state.sqlite` — 원문 변환 결과, 파일 해시, 작업 오류, 실행 이력.
- 결과: `report.json`, 무결성 검사: `verification.json`.
- 저장 결과 정리: `formatting.json`, 읽기 화면: `.preview/*.html` — 읽기를 누를 때 생성합니다.
- 파일명 변경 복구 기록: `.note-moves/*.json` — 변경 완료 후 지워지며, 중단 시 다음 정리·백업에서 복구합니다.
- 변경 전 버전: `history/<blog_id>/<post_id>/<sha256>.md`.

Markdown과 이미지·출처는 상대 링크로 연결되어 일반 Markdown 뷰어와 Obsidian에서 열 수 있습니다. 작성일은 원문 메타데이터에서 확인할 수 있을 때만 기록합니다. 영상/오디오는 원문 링크로 남기며 바이너리를 저장하지 않습니다.

기존 백업 폴더 루트의 Markdown은 앞부분 메타데이터에 들어 있는 네이버 원문 주소로 식별합니다. 파일 존재만으로 성공 처리하지 않고 다시 수집하며, 기존 이름을 유지하고 변경 전 파일을 `history`에 보관합니다. 원문을 가져올 수 없으면 기존 파일을 유지하고 실패를 기록합니다.

새 프로그램이 관리하기 시작한 뒤 사용자가 Markdown을 수정하면 자동 덮어쓰기를 중단하고 부분 성공으로 보고합니다. 백업을 갱신하려면 수정 내용을 별도 위치에 보관한 뒤 해당 파일을 백업 폴더 밖으로 이동하고 `backup`을 재실행하세요. 수정 내용의 자동 병합은 지원하지 않습니다.

파일 교체는 임시 파일과 원자적 교체를 사용합니다. 교체 예정 해시를 DB에 먼저 기록해 파일 교체 직후 종료된 경우도 복구합니다. 동일 폴더에 두 백업을 동시에 실행할 수 없습니다. 상태 DB를 지우면 복구 정보가 사라지므로 Markdown·이미지와 함께 보관하세요. 기존 첨부 및 버전 이력의 자동 삭제는 수행하지 않습니다.

## 결과 해석

글 상태는 `pending`, `running`, `partial`, `success`, `failed`입니다. 본문이 정상이더라도 요청한 이미지나 직접 추적하는 출처가 빠지면 부분 성공입니다. 출처가 다른 출처를 인용한 경우 전체 실행 결과는 추적 범위 내 모든 글의 상태를 합산합니다.

목록의 전체 개수 값만으로 수집을 끝내지 않고 빈 페이지까지 확인합니다. 반복 페이지·알 수 없는 응답 구조·HTTP 오류·페이지 상한은 목록 미완료로 보고합니다. 네이버가 공개하지 않거나 목록에 포함하지 않는 글까지 발견할 수 있다는 뜻은 아닙니다.

종료 코드:

| 코드 | 의미 |
|---|---|
| 0 | backup 완료, verify 통과, reformat 완료, 또는 status 조회 성공 |
| 1 | 부분 백업, 검증·정리 확인 필요, 또는 환경 진단 실패 |
| 2 | 설정·파일·실행 오류 |
| 130 | 사용자 중단 |

`verify`는 네트워크에 연결하지 않고 파일 존재·해시·출처 저장 상태를 확인합니다. 누락·변경은 상태에 반영되며 다음 `backup`에서 복구합니다. 원문과의 최신 일치 여부는 `--refresh`로 확인하세요. `status`는 마지막 실행 상태를 표시합니다.

## 일반 설치 및 개발 검증

```powershell
python -m pip install .
python -m playwright install chromium
naver-blog-archive doctor
naver-blog-archive-gui
naver-blog-archive backup --config C:\path\to\config.toml
```

개발 테스트와 배포 파일 생성:

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m build
```

기본 테스트는 네이버 접속 없이 저장·실패 복구·설정 검증·URL 처리·중단 복구·GUI 작업 제어를 검사합니다. 브라우저 테스트는 `NBA_BROWSER_TEST=1`인 환경에서 실행합니다. 배포 검증에서는 wheel을 일반 설치하고 소스 저장소 밖에서 CLI와 백업 테스트를 실행해야 합니다. 검증 환경의 패키지 버전은 `constraints-tested.txt`에 기록합니다.

모듈 책임: `config` 설정 검증·주소 입력·설정 저장, `network` 목록/HTTP/렌더링, `parser` 본문 변환, `assets` 이미지 검증, `state` SQLite, `archive` 복구·저장 흐름, `cli` 명령 및 종료 코드, `jobs` 백그라운드 작업 제어, `gui` Windows 프로그램 창.

## 보존 스크립트

```powershell
.\scripts\run-dev.bat legacy
```

이 명령은 과거 스크립트의 고정 설정을 사용합니다. 새 설정·상태 저장·복구 기능은 `backup` 명령에 적용됩니다. 일반 설치에서는 `legacy --script <기존 스크립트 절대 경로>`로 명시할 수 있습니다.
